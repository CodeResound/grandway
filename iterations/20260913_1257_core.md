Two changes a client can observe indirectly:
- Django REST Framework was raised from 3.16.1 to 3.17.2, closing CVE-2026-73228: below 3.17.2 an oversized JSON or urlencoded body bypasses Django's `DATA_UPLOAD_MAX_MEMORY_SIZE` when read through `request.data`, which every endpoint here does. No request or response shape changed; all 1568 tests pass on the new version.
- `/health/` now reports version `1.1.0`.

## 7. Flows

**Publish a release** (first full exercise of the autonomous path)
1. Preflight found the `[1.0.0]` heading carried no tag and backfilled `v1.0.0` onto `f337227` before anything else.
2. Ten-point readiness audit: nine green, one blocking finding — the Django REST Framework advisory.
3. `release/1.1.0` cut from `dev`; version bump, changelog section, `deploy.md` refresh, security fix.
4. Verification: full CI green, strict validators green, production smoke boot green.
5. Pull request into `main`, CI green, merge commit, annotated tag, GitHub release with artifacts.
6. `main` merged back into `dev`.
   - The `v1.0.0` backfill produced a red verification run, disclosed in the changelog and logged in `.claude/FAILURE.md`; the tag stays as published because tags are immutable.

**Production smoke boot** (evidence this release is deployable, not merely tagged)
1. Scratch PostgreSQL database migrated from empty, scratch Redis, environment supplied through the process environment so nothing could be committed.
2. `check --deploy --fail-level WARNING` clean; `collectstatic --dry-run` clean.
3. All nine mandatory variables refuse to boot when unset.
4. Probes answer 200 over plain HTTP and report the new version; every other path still redirects to HTTPS.
5. A bad-credentials login returns 401 rather than 500, and Redis holds the throttle counters.
   - The fail-closed check for the environment selector needs the repo-root `.env` absent; with a developer `.env` present it legitimately selects development, which is the documented fallback.

## 8. Gaps
- **`v1.0.0`'s verification workflow fails and cannot be made to pass** — the workflow that runs is the one committed at that tag, and the two CI-environment defects it trips on were fixed afterwards. Disclosed in the changelog; `v1.1.0` is the first release whose verification passes.
- The production smoke boot depends on a scratch Redis container. On a machine without one, the throttled-request check must be reported as skipped rather than quietly dropped.
- Dependency currency beyond the security fix was not pursued: Django 5.2.17 has a 6.1.1 available, and several other pins are behind. No advisory affects any of them, so this is currency rather than risk, and a framework major is its own piece of work.
- All eight items in the `### Deferred` registry were reviewed and all eight stay deferred; this release addresses none of them.
