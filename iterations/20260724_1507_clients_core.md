## Clients

### 1. Module

- **Name:** Clients — the B2B partner directory. The agencies, schools, and companies that refer or send applicants.
- **Base path:** `/api/v1/clients/`
- **Auth:** Bearer access JWT on every endpoint. **Reads: Admin and Lead Manager. Writes: Admin only.** Superadmin refused everywhere including reads, with 403 `CLIENTS_ACTOR_FORBIDDEN`.

### 2. Conventions

- **Response:** `{ success, message, data, meta }`. The resource is always under `data`; `meta` is `{}` when there is nothing to report.
- **Error:** `{ success: false, error: { code, message, details }, meta }`. `details` is always present, `{}` when there are no field-level errors.
- **Auth failures:** 401 from the authentication framework with no/expired/revoked token. 403 `CLIENTS_ACTOR_FORBIDDEN` when the token is valid but the authority may not act — covering both a Lead Manager writing and a Superadmin doing anything. The two share one code and differ only in `message`, so branch on `code`. This code replaces the project-wide `PERMISSION_DENIED`, which is never returned from this module.
- **Pagination:** page-number based, `page` and `page_size` (default 20, max 100). `data` is the bare array of rows, not nested under `results`. `meta` carries `count`, `page`, `page_size`, `next`, `previous`; `next`/`previous` are absolute URLs or `null`. Applied to both list endpoints.
- **IDs:** UUID strings. No human-readable code on any resource, unlike `institutions.Country` or `leads.LeadSource`.
- **Times:** `created_at` and `updated_at` are ISO 8601 UTC with no BS sibling. `retired_at` carries `retired_at_bs`, an object or `null`, shaped `{ year, month, day, month_name_en, month_name_np, display_en, display_np }`. No endpoint accepts BS input.
- **List/search/filter params:** `status` (exact enum), `search` (partial match across six name fields), `fiscal_year` (`YYYY/YY`, on `created_at`). Invalid values are rejected with 400, not ignored.
- **Ordering:** fixed, not client-controllable. The directory is alphabetical by `name_np` — **not newest-first**, unlike every other list in the project. History is newest-first.
- **Empty text fields are `""`, never `null`.** The nullable fields are `retired_at`, `retired_by_username`, and `primary_contact_number` on the list shape.
- **`status` and the retirement fields are rejected on `PATCH`, not silently dropped** — the inverse of the `institutions` convention.
- **Contact numbers are a replacement set.** Sending the key replaces every number; omitting it leaves them alone; sending `[]` clears them.

### 3. Models

**Client (list shape)** — `{ id, name_np, name_en, name_romanized, spokesperson_name_np, spokesperson_name_en, email, primary_contact_number?, status:[enum], is_active, logo_url, updated_at }`

- `primary_contact_number` is a flat string or `null`, not an object — the number flagged primary, else the first recorded.
- Omits `website`, `address`, `notes`, the spokesperson designation and romanized name, and the full number list.

**Client (detail shape)** — `{ id, name_np, name_en, name_romanized, spokesperson_name_np, spokesperson_name_en, spokesperson_name_romanized, spokesperson_designation, email, website, logo_url, address, contact_numbers:list[ContactNumber], status:[enum], is_active, status_note, retired_at?, retired_at_bs?:json, retired_by_username?, notes, created_by_username, created_at, updated_at }`

- Returned by retrieve, create, update, retire, and restore. Only the list returns the shorter shape.
- `name_romanized` and `spokesperson_name_romanized` are auto-derived ASCII search keys, not display fields — `"हिमाल एजुकेशन"` becomes `"himala ejukesana"`. Render `name_en` if present, else `name_np`.
- `status_note` is non-empty only when `status` is `inactive`; restoring clears it.
- `address` is one free-text field, not a structured object.

**ContactNumber** — `{ id, number, label:[enum], is_primary }`

- On write send `{ number, label?, is_primary? }` — the `id` is neither accepted nor needed.
- `is_primary` is neither unique nor required: a client may have zero primary numbers or several. The array is ordered primaries-first.

**HistoryEvent** — `{ id, action, actor_type:[enum], actor_label, summary, reason, changes:json, metadata:json, created_at, created_at_bs:json }`

- `changes` maps field name to `{ from, to }`, both stringified; `{}` on creation events.
- A contact-number replacement appears as `changes.contact_numbers = { "from": "replaced", "to": "N number(s)" }` — a marker, not a before/after list of the numbers.

### 4. Enums

- `Client.status`: `active` | `inactive`
- There is no `paused` or `archived` value; the reason for a retirement lives in `status_note` as free text
- `ContactNumber.label`: `mobile` | `home` | `work` | `whatsapp` | `viber` | `other` — the same value set as `leads` and `applicants` contact numbers
- `HistoryEvent.action`: `client_created` | `client_updated` | `client_retired` | `client_restored`
- `HistoryEvent.actor_type`: `superadmin` | `admin` | `lead_manager` | `system` | `ai`. In practice only `admin` appears, since only Admins can write
- `spokesperson_designation` is **not** an enum — free text

### 5. Dependency order

- `Client` needs nothing. It is a root record with no parent, no external reference, and no prerequisite.
- `ContactNumber` needs a `Client`, but is never created independently — it arrives inside the client payload.

**Start here:** `POST /api/v1/clients/` as an Admin. This is the only module in the project that can be populated from a completely empty database without touching anything else.

### 6. Endpoints

#### Client — `/api/v1/clients/`

**Use it when:** the Client List directory, the Client Detail screen, and the New / Edit Client form.

**Methods:**
- `GET /api/v1/clients/` — `clients.client.list`
- `POST /api/v1/clients/` — `clients.client.create`
- `GET /api/v1/clients/<client_id>/` — `clients.client.read`
- `PATCH /api/v1/clients/<client_id>/` — `clients.client.update`

**Send (create/update):**
- create: `name_np` required; optional `name_en`, `name_romanized`, `spokesperson_name_np`, `spokesperson_name_en`, `spokesperson_name_romanized`, `spokesperson_designation`, `email`, `website`, `logo_url`, `address`, `notes`, `contact_numbers`
- update: any subset of the same fields, with `name_np` optional — and nothing else

**Returns:** Client (detail shape) for create, retrieve, update; list[Client (list shape)] for the list.

**Notes:**
- Only `name_np` is required. The spokesperson and every contact number are optional.
- `name_romanized` and `spokesperson_name_romanized` are auto-derived from their `_np` source when not supplied, and a supplied value is never overwritten — including on a later edit.
- `search` covers six fields: the organization's three names and the spokesperson's three.
- Omitting `status` returns both active and inactive clients.
- Sending `status`, `status_note`, `retired_at`, or `retired_by` on update returns 400 with each offending field in `details`.
- Contact numbers replace rather than append; `null` and `[]` mean different things.
- Defaults: `status` is `active`, every text field is `""`, `contact_numbers` is `[]`.
- Reads are open to Lead Managers; writes are Admin-only.
- There is no delete.

**Errors:**
- `CLIENTS_STATUS_IMMUTABLE` (400) — a PATCH carried a standing field
- `CLIENTS_CONTACT_NUMBER_DUPLICATE` (400) — the same number appears twice in one payload
- `CLIENTS_CLIENT_NOT_FOUND` (404)

#### Client: retire — `/api/v1/clients/<client_id>/retire/`

**Use it when:** the Client Detail retire action — the relationship has ended or paused.

**Methods:**
- `POST /api/v1/clients/<client_id>/retire/` — `clients.client.retire`

**Send:** `reason`, required and non-empty.

**Returns:** Client (detail shape) with `status` now `inactive`, `status_note` set, and `retired_at` / `retired_by_username` stamped.

**Notes:**
- Only an active client may be retired.
- The reason is mandatory: retired clients are kept forever, so why one is inactive must be answerable from the record.
- Retiring does not remove the client from unfiltered list results.
- Admin only.

**Errors:**
- `CLIENTS_CLIENT_ALREADY_RETIRED` (409)
- `CLIENTS_STATUS_NOTE_REQUIRED` (400) — reason missing or blank
- `CLIENTS_CLIENT_NOT_FOUND` (404)

#### Client: restore — `/api/v1/clients/<client_id>/restore/`

**Use it when:** the Client Detail restore action — the consultancy is working with this partner again.

**Methods:**
- `POST /api/v1/clients/<client_id>/restore/` — `clients.client.restore`

**Send:** nothing.

**Returns:** Client (detail shape) with `status` back to `active` and `status_note`, `retired_at`, `retired_by_username` all cleared.

**Notes:**
- Only a retired client may be restored.
- Clearing the retirement fields does not erase the retirement from history — `client_retired` and its reason stay in the history endpoint.
- Admin only.

**Errors:**
- `CLIENTS_CLIENT_NOT_RETIRED` (409)
- `CLIENTS_CLIENT_NOT_FOUND` (404)

#### Client: history — `/api/v1/clients/<client_id>/history/`

**Use it when:** the history or audit-trail panel on the Client Detail screen.

**Methods:**
- `GET /api/v1/clients/<client_id>/history/` — `clients.client.list_history`

**Send:** nothing.

**Returns:** list[HistoryEvent], newest first, paginated.

**Notes:**
- Readable by a Lead Manager, unlike every write in this module.
- Never empty for an existing client — creation always writes one event.
- The only place a retired-then-restored client's past retirement is visible.

**Errors:**
- `CLIENTS_CLIENT_NOT_FOUND` (404)

### 7. Flows

**Add a partner to the directory**

1. `POST /api/v1/clients/` with `name_np`, the spokesperson, and a `contact_numbers` array. Returns the client id at `status: active`.
   - Missing `name_np` → 400 `VALIDATION_ERROR` with `details.name_np`.
   - The same number twice → 400 `CLIENTS_CONTACT_NUMBER_DUPLICATE`.
   - Called by a Lead Manager → 403 `CLIENTS_ACTOR_FORBIDDEN`; the button should not have been shown.
2. Do not display `name_romanized` from the response — it is the search index and will look wrong to a human.

**Find the right partner**

1. `GET /api/v1/clients/?status=active&search=<query>` — one box searches both the company name and the spokesperson's, in Devanagari, English, or Roman transliteration.
2. Render `primary_contact_number` and `email` straight from the list row; no detail fetch is needed for a phone-and-email directory.
3. `GET /api/v1/clients/<id>/` for the other numbers, website, address, and notes.
   - A Lead Manager may do all of this; only the edit controls are refused.

**Retire and later restore a partner**

1. `POST /api/v1/clients/<id>/retire/` with a reason. Returns `status: inactive` with `retired_at` stamped.
   - No reason → 400 `CLIENTS_STATUS_NOTE_REQUIRED`.
   - Already retired → 409 `CLIENTS_CLIENT_ALREADY_RETIRED`; refetch.
2. The client still appears in the unfiltered list. Grey it out or move it to an inactive section — the API will not hide it.
3. `POST /api/v1/clients/<id>/restore/` returns `status: active` with the retirement fields cleared.
4. `GET /api/v1/clients/<id>/history/` still shows `client_retired` with the original reason.

**Correct a partner's contact details**

1. `GET /api/v1/clients/<id>/` for the current record.
2. `PATCH /api/v1/clients/<id>/` with only the changed fields.
   - Sending the whole object back, including `status`, → 400 `CLIENTS_STATUS_IMMUTABLE`.
   - To change the numbers send the complete new array; to clear them send `[]`; to leave them alone omit the key.
3. A PATCH that changed nothing returns 200 and writes no history event.

### 8. Gaps

- **Attribution is not built.** There is no `client` field on a lead or an applicant, no `?client=` filter anywhere, and no referral count, statistic, or report. A client record cannot be connected to a single person the partner referred. This is the concept's flow 3 and it has no endpoints.
- No `client_type` field — agencies, schools, and partner companies are the same shape and cannot be filtered apart.
- `logo_url` is an unvalidated external URL: stored as given, never fetched or checked, and pointing at a third-party host.
- `is_primary` on a contact number is neither unique nor required; a client may have zero primary numbers or several.
- Contact-number history is a marker, not a diff — you cannot recover which number was removed or added.
- The address is one unstructured text field, so no geographic filtering or grouping is possible.
- No duplicate detection: two clients may share a name, email, and number with no warning.
- Only the organization-name fields are trigram-indexed; the spokesperson half of a search is a sequential scan. Deliberate at this table's size.
- No bulk import — partners are added one at a time, with no CSV path and no management command.
