## 7. Flows

**Upgrade a deployed host to `v2.0.0`**
1. Read the `2.0.0` release notes; the version is MAJOR, so a human confirms the matching frontend build ships with it.
2. Snapshot, check out `v2.0.0`, and run the upgrade sequence in `deploy.md` §16 (Upgrade sequence).
3. Restart rather than reload — the Django pin changed to `5.2.18`.
   - The nine migrations are additive; none needs an off-peak window.
   - The four new environment variables are optional with safe defaults; no env file edit is required.
4. From the first nightly sweep onwards, notifications that are event alerts or resolved alerts older than 90 days are deleted (`deploy.md` §13 (Scheduled jobs)).

**Client behaviour that changes in place on `/api/v1/`**
1. `GET /documents/` omits archived documents unless `status=archived` or `include_archived=true` is sent.
2. `POST /applicants/<id>/status/` rejects moving an applicant out of `archived` with `APPLICANTS_APPLICANT_ARCHIVED` (409); un-archive with `POST /applicants/<id>/restore/` (Admin only).
3. Writes to a converted lead's notes return 409.
4. The refresh cookie persists for the 7-day absolute session lifetime.
